Design and motion principles

How an interface looks, reads, behaves and moves. Eight principles decide what to build; the rules below say how. The Do specimens on this page follow them. Switch on the editor layer to add the rules for editors and workspaces.

How to decide

When two rules pull against each other, these eight break the tie. They decide what to build as much as how it looks.

Purpose

Every feature asks for people’s time, attention and trust. Spend that budget only where it pays, and decide what not to build.

Agency

Offer choices, keep a way back, and make undo the safety net. Confirm only what is costly and can’t be undone.

Responsibility

Ask for private data only when it’s needed, only for what’s needed, and say what happens to it. Anticipate how the product could mislead or harm.

Familiarity

Build on what people know, and keep the same-looking thing in the same place behaving the same way. Break a pattern only when the new one is better.

Flexibility

One layout rarely fits every device, language and pair of eyes. Adapt to the platform and let people adjust what they see.

Simplicity, not minimalism

Cut what doesn’t serve the purpose; hiding everything to look clean is not simple. The common path comes first, rare options one step deeper.

Craft

Every spacing, timing and alignment value is a deliberate choice you can defend. Jitter and misalignment read as carelessness.

Delight

The result of getting the other seven right, not confetti on top. Decide the feeling you want, then reinforce it everywhere.

Layout and spacing

Space shows what belongs together

The gap between groups is at least twice the gap inside one, like 8px inside and 16px between. Gaps and padding come from a small spacing scale, never a number typed into one component.

A control sits with what it changes

Place it next to the thing it affects and arrange controls to mirror what they change. If a label has to explain the mapping, move the control.

Same thing, same size, same line

Rows in one list share one height and one gap. Icons sit in one column, labels start on one line, numbers align right. Line things up by eye, not by the numbers: a triangle needs a small nudge to look centred, and a button gets less padding on its icon side.

Nothing scrolls sideways

If something doesn’t fit, it wraps. Vertical scroll is fine. The exception is content that is wide by nature, like a data table or a map.

Editor

A calm, dense tool

A tool people work in for hours fits a lot on screen and stays steady: little layout variety, panels that keep their place and shape. The variety goes into the content.

Editor

Open beside, not instead

Settings, menus and side panels open as trays next to what you clicked, so you never lose your place. Full screen swaps are for leaving the current task.

Editor

Group by what it changes

Controls that change the same thing sit together in one section, not spread across cards.

Editor

Panels never scroll sideways

Core allows wide content like a table. A panel has no such exception: if something doesn’t fit, it wraps. Vertical scroll is fine.

Colour and surfaces

Surfaces stay quiet

Neutral surfaces with one accent. If the chrome draws the eye away from the main content, it is too loud.

One accent, one job

The accent is the brand colour. It marks what’s selected, switched on, or the main action. Call it accent, never primary. One primary button per view. Text on the accent uses its own ink colour, never grey.

Three text roles

One colour for what you read, a muted one for secondary text and icons, a faint one only for meta like counts. No in-between greys.

A shadow means it floats

Only things above the page get a shadow: menus, popovers, dialogs. Inside a surface, depth is a step lighter, never an outline or a divider. A selected row is a surface step, not a glow.

Decoration has to do a job

No glows, glass, blurred blobs, gradient text or emoji. A gradient is allowed only as a small tone shift inside one colour, never from one hue to another.

Nested corners are concentric

The inner radius is the outer radius minus the padding between them, so the two curves run parallel.

Images get a hairline edge

A 1px outline set 1px inside the image: black at 8% in light mode, white at 8% in dark. It stops a pale image bleeding into the surface. It’s the one border and the one tint allowed outside the ramp.

Values come from tokens

Colours, radii, spacing, durations and easings come from one set of tokens, named for their job, never for their value. Every step in a scale has a use. If a token is wrong, change the token.

Dark mode is its own palette

Build it on purpose instead of inverting light mode. Check contrast against the surface directly behind each element, not the page.

Editor

Panels stay quiet

Panels use neutral surfaces with one accent. If a panel draws the eye away from the main content, it is too loud.

Editor

Corners follow the role

One radius for floating panels, a smaller one for cards inside them, pills for controls. The card’s radius is the panel’s radius minus the padding, so the corners stay concentric. No card inside a card.

Type, words and icons

Two typefaces, each with a job

A sans for everything you read. A mono only for codes and values you compare. Timers, prices and tables use tabular figures so they don’t shift.

Hierarchy from size and colour, not weight

Reach for a bigger size or a stronger text role before a heavier weight. No italic emphasis, no negative letter spacing on small text, sentence case everywhere.

Type is tuned per size

Leading tightens as text grows and loosens for body copy; large text takes slight negative tracking, small text a little positive. Set spacing in rem so the layout grows with the reader’s text size. Body text runs 60–75 characters per line, and headings balance their line breaks.

Labels name things; they don’t give instructions

“Colours” is enough. Drop helper lines and readouts nobody acts on. No trailing periods or exclamation marks. Placeholders are short. A toggle says what happens when it’s on, and a link says where it goes.

Buttons say what happens

Verb plus object. No “Get started” or “Learn more”, no marketing words like seamless, supercharge, elevate or unlock, and no made-up numbers. A confirmation repeats the action, like “Delete project” beside “Cancel”, and a flow uses one label for every next step.

Talk to the reader

Address people as “you”, never “the user”.

Punctuation is typographic

Curly quotes, an en dash for ranges, an em dash for asides, and the ellipsis character instead of three dots. Write in normal case and let styling change it.

Cut text stays reachable

When text is cut with an ellipsis, the full text is in a tooltip or an expanded view. Long words, links and IDs wrap inside their container.

One icon set, used where it helps

One set, one size scale, the colour and stroke weight of the text beside it, in a fixed-width box. An icon-only button always has a tooltip and an accessible name.

Editor

Live values are mono and tabular

Counts and values you compare use the mono typeface. Numbers that change while you watch use tabular figures, in one format across a panel, so they don’t jiggle.

Editor

Readouts earn their place

A value shown in a panel is one someone acts on. “Opacity” next to a slider is enough.

Editor

Panel words are short

Labels name things, buttons are verb plus object, and placeholders are a word or two.

Interaction and states

Every control shows its state

Resting, hover, pressed, selected, on and disabled each look different. Hover is a colour change; buttons never grow. Press shrinks slightly; selected and on use the accent.

Answer on press

Press shows on pointer-down and commits on release; sliding away cancels. Feedback continues for as long as the gesture lasts, not only at the end.

The thing follows the finger

A drag tracks 1:1 from where it was grabbed, not from its centre. A short threshold decides the direction, then it commits; past the end it resists and springs back. Arrow keys move it too.

Say why something is off

A disabled control gets a short tooltip with the reason and the way out. A form’s submit button is the exception: it stays enabled, and the form is checked when it’s sent.

Hover only where there’s a mouse

Hover styles sit behind a media query so a tap on a phone doesn’t leave them stuck.

Undo beats a confirmation

Give people a way back from a mistake. Confirm only what is destructive and can’t be undone.

Say what happened

Status, success, warning and error each have a place. Put an error where the problem is, not only in a summary after submit. Colour is never the only signal.

Every screen answers where you are

Where am I, what can I do here, and how do I leave. Never a dead end. An empty view says what belongs there and offers one action to start.

Accessibility

Native elements first

A button is a button and a link is a link, so keyboard, screen reader and browser behaviour come for free. Tab order follows the page.

Focus is always visible

Keyboard focus shows a ring. Never remove an outline without putting something as clear in its place.

Hit areas are big enough

At least 24 by 24px. Aim for 44 by 44px on touch screens and 40 by 40px with a mouse. Hit areas never overlap.

Every input has a visible label

The field type and keyboard match what goes in. Never block paste; people paste passwords and one-time codes.

Name what can’t be seen

An icon-only button has an accessible name. Alt text says what an image shows and why it’s there; a decorative image has empty alt text.

Errors are found on submit

Keep the submit button enabled. Check the form when it’s sent, mark each invalid field, tie each error to its field, and move focus to the first one.

Announce at the right volume

Routine updates are announced politely. Only urgent errors interrupt.

Slop to avoid

Things that make an interface look generated. Leave them out and do the plain thing instead.

Tags and badges

No “New” or “Beta” pills. Say it in words where it matters, or not at all.

Italic words

No italics for emphasis or flavour. A logo can be the exception.

Editorial serifs and negative kerning

No serif display type, and no tightened spacing to make headings look designed.

Over-detailed UI

Every extra line, tick, label and tiny icon has to earn its place. When in doubt, take it out.

Dividers

Separate groups with space, not lines.

Many shades and opacities

Use the ramp steps and the three text roles. No new tints of a colour. An image’s hairline edge is the one exception.

Containers with borders

Space and a surface step do the grouping. A floating layer’s outer edge and an image’s hairline edge can be the exception.

Diagrams

Only when one is really needed, and as simple as it can be.

Code breadcrumbs

No file paths, token names or trails in the interface. Say it in words.

Section numbering

No “01” or “1.” in front of section titles.

Motion

Content is allowed to move as much as it likes. The interface around it moves only to explain a change.

Animate by how often it happens

The more often someone does a thing, the less it should move.

Editor

Constant actions don’t move

Dragging a slider, scrubbing a value, undo and redo, picking a layer, and nudging with arrow keys get no motion, or a colour change only. A selected item is a surface step.

Editor

Panels open as trays

A tray slides out from the edge it’s attached to on the drawer curve, 250ms in and 150ms out. Whatever sits beside it steps aside with the same timing and direction.

Nothing appears out of nowhere

New UI comes from the thing that opened it. A drawer slides from its edge, a menu grows from its button, a dialog with no trigger scales from its centre.

Leave the way you came

Exit along the path it entered, with the easing mirrored, so the way out matches the way in.

Motion never blocks input

You can click, type or drag the moment something starts opening. Use CSS transitions for anything that opens and closes, because a transition can reverse halfway and a keyframe restarts from zero.

Start from where it is

An interrupted animation picks up from its current on-screen value and speed. Chrome that opens and closes uses a transition, which can reverse halfway; anything a finger drags or throws uses a spring, which takes a new target and keeps moving.

Carry the throw

When a drag ends, hand its speed to the animation and send it where the throw was going, not to the nearest edge from where the finger left.

Edges give

At a boundary, resist more the further it’s pushed, then spring back on release. A hard stop reads as frozen.

Leave faster than you arrive

Exits are about half the enter time. A drawer that opens in 250ms closes in 150ms. Exits are smaller too: a shorter move, a fade and a 4px blur.

Exits blur a little

On the way out, a card moves 4px, fades and blurs by 4px. On the way in it only fades and moves.

Ease out, never in

Enter and exit use ease-out. Something travelling across the screen uses ease-in-out. Drawers use the drawer curve. An ease-in curve holds back right when the person is waiting.

Start close to the end

Enter from scale(0.95) with opacity 0, or a 4px to 8px nudge. Never from scale(0).

One change, one movement

When one thing opens and another steps aside, they share timing and direction so it reads as one event.

Only move what’s cheap

Animate transform, opacity and colours, plus a blur of 4px or less on exits and icon swaps. List the properties; never transition: all. Height animations stay short because they cost layout on every frame.

Icons swap in place

The old icon fades out as the new one fades in. The new one scales from 0.25 to 1 and goes from a 4px blur to sharp; the old one does the reverse.

Enter in small groups

A list arrives in a few groups with a short stagger between them, not item by item and not as one block.

Nothing moves on arrival

Nothing animates on page load unless that moment was designed. Switching between light and dark mode turns transitions off, so every colour changes in the same frame. This page does both.

Sound and haptics land on the same frame

Fire them on the cause, on the same frame as the visual, and keep them for commit, success and error. Anything more trains people to ignore them.

Bounce follows momentum, and nothing loops for attention

A release that carried speed can overshoot. A loader can too. A control that simply appeared doesn’t. A loader is the only thing that loops, and only while you’re waiting.

Reduced motion gets the same end state

With reduced motion on, things fade instead of move, and nothing depends on seeing the animation to make sense. Reduced transparency makes floating surfaces solid; more contrast gives edges a defined boundary. Neither loses information.

Watch it before you ship it

Build the interaction before you judge it, because motion and visuals are designed together, not in layers. Play it at normal speed, then slowed down 5x, and look at the frames in between. Look again the next day.

Build notes for the web

How to meet the rules above in HTML and CSS.

Type

Ship .woff2. Font smoothing on the root. tabular-nums for changing numbers. text-wrap: balance on headings, pretty on descriptions. overflow-wrap: break-word for long words. text-underline-position: from-font.

Colour

One way to switch themes: prefers-color-scheme or a .dark class, never both. in oklab keeps a gradient’s brightness even.

Images

outline: 1px solid rgb(0 0 0 / 0.08); outline-offset: -1px, with white in dark mode.

Motion

Animations inside prefers-reduced-motion: no-preference. will-change: transform if something jitters by 1–2px, mostly in Safari on iOS. transform-origin from the trigger.

Accessibility

Style :focus-visible. Only tabindex 0 and -1. No aria-hidden on focusable things. aria-invalid and aria-describedby on errors. pointer-events: none on decorative layers.

Layout

scroll-margin-top on headings so a link doesn’t land under a sticky header.
